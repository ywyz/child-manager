# ADR-0012：本地优先桌面产品方向重置

- 状态：已确认
- 日期：2026-08-08
- 决策者：项目维护者
- 取代范围：ADR-0009、ADR-0010、ADR-0011 中面向首期 Cloud/B/S 产品的部署、入口、
  身份与恢复结论；这些文档保留为历史，不再驱动桌面首期实现

## 背景

现有 `child-manager` 以完整幼儿园信息管理系统为目标，采用 NiceGUI Web、FastAPI API、
PostgreSQL、Redis 和独立 Worker，并实现了账号、权限、多园隔离、异步任务和公网部署前置
安全边界。对个人开发者而言，这些平台能力显著扩大了首个可用产品的实现、部署和维护成本。

维护者已经确认将产品正式重置为“幼儿园管理助手”：一个本地优先、模块化的桌面系统。
一日活动计划是首个完整模块，不是产品最终边界。旧 `kindergartenManager` 的数据和本仓库
PostgreSQL 数据均不迁移。

## 决策

1. Windows 为首发平台，应用采用 Python 3.14、PySide6 和 Qt Widgets；Linux 用于开发，
   macOS 保持代码兼容但不属于首期发布验收。
2. 应用为单进程桌面程序，不启动本地 HTTP 服务，不依赖浏览器、FastAPI、Redis 或独立
   Worker。SQLite 是本机业务数据唯一权威。
3. 首期面向单教师，可管理多个班级，不提供账号、角色、认证、多园隔离或多人并发。
4. 产品显示名为“幼儿园管理助手”，目标仓库名为 `kindergarten-manager-desktop`，稳定应用
   标识为 `cn.kindergartenmanager.desktop`，Python 根命名空间为 `kindergarten_manager`。
5. 首期不保存幼儿姓名、照片或其他个人信息。未来观察记录、一对一倾听等模块必须先完成
   独立隐私与存储设计。
6. AI 是可选联网功能。只保留一个当前 OpenAI 兼容模型配置、内置可编辑提示词和后台单任务
   执行；未配置 AI 时手工教案和 Word 导出完整可用。
7. 本地备份是基础能力。WebDAV/S3 仅保存本机加密后的单向备份，不提供多设备同步或冲突
   合并。凭据和可自动备份使用的恢复口令进入操作系统凭据存储。
8. 首期提供标准 Windows 安装包；后期同时提供 Microsoft Store MSIX 与未签名 EXE。Store
   负责 MSIX 签名和更新，EXE 只提示新版本并打开官方下载页。
9. 首期 AI 覆盖四栏生成、单栏生成和一日活动反思。`.docx` 原始教案导入、AI 拆分/补全与
   新增适龄环节是下一期必做范围，不得无限延期。

## 取舍

### 收益

- 去除平台、部署、认证和多服务运维成本，缩短真实教师可用产品的交付路径。
- 保留 Python 领域规则、AI 结构校验和固定 Word 模板等已有高价值资产。
- 本地离线主流程降低网络依赖；单向加密备份提供可恢复性而不引入同步复杂度。

### 代价

- 现有 Web/API/Worker/认证与 PostgreSQL 实现不直接进入桌面首期。
- 桌面 UI、SQLite Schema、Windows 打包和操作系统集成需要新的实现与验收。
- 单机版不支持多人协作、跨设备实时同步或集中管理。

## 被否决方案

### 将现有 B/S 系统封装进桌面窗口

仍需运行本地服务、端口和浏览器渲染层，重复旧 `kindergartenManager` 已被维护者认为体验不佳
的路径，未实质降低架构复杂度。

### 使用 PyQt6

PyQt6 支持 Python 3.14，但其 GPLv3/商业许可不如 PySide6 的 LGPL/GPL/商业选择适合当前
分发计划。PySide6 同时是 Qt 官方 Python 绑定并提供官方部署工具。

### 首期同时建设 Cloud 和桌面版

个人开发无法为两套运行模型提供同等质量保证，也会迫使领域层长期承载未被真实需求证明的
抽象。Cloud、协作和同步只有在桌面产品出现真实需求后才能重新设计。

## 迁移与后续

- 当前 `design/desktop-local-first` 只承载设计和可丢弃原型，不迁移正式业务实现。
- 受控 Agent 的单 Agent、Tool-only、确认写入和无长期业务记忆决策由
  [ADR-0013](ADR-0013-controlled-agent-runtime.md) 细化，不改变本 ADR 的本地优先与教师控制边界。
- 设计确认后，将事实文档收敛到 `docs` 并固定完整 docs SHA 创建新的实现 Issue。
- 实现必须从新的 `dev` 基线开始，旧 B/S 测试只能作为规则参考，不能证明桌面验收完成。
- 远端仓库、本地目录和 GitHub 设置的重命名需要独立授权。
